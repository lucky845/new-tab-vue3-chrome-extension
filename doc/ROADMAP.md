# New Tab Pro 迭代路线图

> 版本：v2.0.0 起点 · 制定日期 2026-11-16 · 单人维护
> 依据：三份独立专家报告（用户反馈 / 需求优先级 / 竞品与上架）+ 仓库实测核实

---

## 0. 一句话定位

**New Tab Pro 是唯一把「液态玻璃材质」做成产品骨架，同时把 iTab 级功能密度塞进一个零账号、零云、零遥测的本地新标签页。**

英文：_A liquid-glass new tab that packs iTab-level density into a zero-account, zero-cloud, zero-telemetry local page._

### 市场空位（竞品分析结论）

| 产品                 | 用户量  | 评分                | 路线                     | 短板                        |
| -------------------- | ------- | ------------------- | ------------------------ | --------------------------- |
| Infinity New Tab Pro | 300,000 | 4.7                 | 免费 + Pro 订阅 + 联盟位 | 商业化重，云同步=隐私面     |
| iTab 新标签页        | 300,000 | **3.1**（867 评分） | 免费 + 会员              | 重功能轻稳定，卡顿/同步差评 |
| Momentum             | —       | —                   | US$39.95/年              | 付费墙前置，中文场景为零    |
| Tabliss              | —       | —                   | 免费开源 MIT             | 功能薄，需自备 API Key      |
| Bonjourr             | —       | —                   | 免费开源                 | 功能浅，无文件夹/工具矩阵   |
| WeTab                | —       | —                   | ¥19.9/月 或 ¥149/年      | 异化成 AI 工具站入口        |

**中间那格是空的**：有 iTab 的功能密度，但用 Bonjourr 的隐私承诺和更好的视觉。iTab 3.1 分证明这格需求真实存在且被服务得很差。

### 三道护城河

1. **材质一致性是系统工程**：css-svg 折射后端 + MV3 CSP 下 `worker-src blob:` 被拒后的主线程位移贴图降级 + 首屏同步主题引导防白闪。竞品要抄，得重做渲染层并接受 CSP 下的性能取舍。
2. **指针事件自研拖拽的手感**（`src/composables/useIconDrag.ts`）：换位补间、悬停合并、停留建文件夹。这类手感只能靠反复调参，库给不了。
3. **「纯本地」是架构承诺而非营销话术**：无后端无账号无埋点。竞品想做同样承诺，必须先拆掉云同步——那是它们的收入来源。**护城河的本质是商业模式不兼容。**

## 2. 优先级方法（单人版）

### 评分公式

```
S = (V × R) / C

V  用户可感知度 1–5    5=不装也能从截图看出来 / 1=只有开发者能感知
R  基础设施复用度 1–3   3=复用≥70%已有代码 / 2=部分复用 / 1=从零
C  有效人日 1–5        已含三浏览器回归与文档，单人负荷系数 1.4 内建
```

| S     | 处置                                |
| ----- | ----------------------------------- |
| ≥ 6   | 本版必做（速胜项）                  |
| 3–6   | 排进本版余量                        |
| 1.5–3 | 进 BACKLOG，等 R 升高后重算         |
| < 1.5 | 不做，写进 NOT-DOING 并注明重开条件 |

**不用 RICE/ICE 的理由**：Reach 在本项目拿不到数据（无埋点无账号），这一项占 25% 权重却全是噪声；Confidence 在单人评审里等于"我有多想做"。而 C 维度必须区分"有没有现成基础设施"——历史管理复用 `useSearch.ts` 已有方法 C≈1.5，多引擎聚合要从零建并发调度 C≈6，这个 4 倍差是 RICE 给不出的。

### 例外条款（防止公式误杀）

横切型工作（i18n、命令式 DOM 收敛）C 巨大而 V 低，但**不做会让后续每个功能都变贵**。这类只允许以"整版专项"进入，不接受拆碎后按公式排序——否则永远排不上。

## 3. 版本规划

| 版本     | 主题   | 体验 : 新功能 : 技术债 | 目标                        |
| -------- | ------ | ---------------------- | --------------------------- |
| **v2.1** | 能上架 | **35 : 25 : 40**       | 首发三商店 + 铺好回归安全垫 |

**配额理由**：体验是"公共成本"，改一处 CSS/组件让功能与债务同时受益，几乎不新增回归面，所以三档都给 25–35% 稳定配额。v2.1 债最高（40%）因为当前 `lint` 只 lint 配置文件本身、CI 只有 `compile`、零测试——这个状态下扩张功能是在没有回归保护的情况下推进。v2.2 功能最高（55%）因为安全垫已铺好，且单人项目的功能窗口有时效。v3.0 债回升因为 i18n 与聚合搜索都是横切全仓。

    - 现状：`wxt.config.ts` host_permissions 最后一项，构建产物如实带上
    - 影响：触发最小权限原则审核整改；即使过审也显示"读取你在所有网站的数据"

- [x] **新建 `PRIVACY.md` 并发布到 GitHub Pages**
    - Chrome 政策：处理任何用户数据必须提供隐私政策且填 dashboard 链接，**无政策必然审核不过**

## 11. 排期陷阱与对策

| 陷阱                   | 表现                                                      | 对策                                                                       |
| ---------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- |
| **幽灵完成**           | 本地 dev 能跑就以为完成；CI 只跑 compile，样式/运行时全漏 | CI 当 reviewer：lint+test+build 三件套必须绿；UI 项 PR 必须贴截图          |
| **技术债永远等下一版** | 49 处陈旧注释每版都说下次清                               | 债写进配额（v2.1 给 40%）+ 单设「顺手 30 分钟清单」，PR 收尾有余量就挑一条 |
| **PR 自审空转**        | 分支保护有了但没人 review                                 | PR 模板 checklist 替代 reviewer；self-merge 需 CI 绿 + 至少 1 小时冷静期   |
| **大重构吞掉发布节奏** | `useTip.ts` 想一次改干净，两周没发版                      | 单 PR ≤ 400 行、只动一个 composable；**主分支永远可发布**                  |
| **乐观估时**           | 估 3 天做 6 天                                            | 已内建 load factor 1.4；每版 +20% 缓冲吸收打包/审核/浏览器差异             |
| **无遥测所以拍脑袋**   | 需求靠"我觉得"                                            | 只用三个信号：Issue 关键词频次、Release 下载数、自己一周真实使用记录       |
| **范围蔓延**           | 版本做着做着又加想法                                      | 版本冻结后新想法进 BACKLOG；**版本内 PR 上限 8 个**                        |
| **商店审核返工**       | 功能做完才提交被打回                                      | 上架前置检查放 v2.1 第一周做完再开工功能                                   |
